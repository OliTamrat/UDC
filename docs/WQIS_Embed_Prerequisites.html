WQIS Dashboard Embedding

Prerequisites & Technical Requirements for UDC WRRI Website Integration
Document Version: 1.0  |  Prepared: July 1, 2026  |  Classification: Internal / UDC IT

1. Purpose

This document outlines the technical prerequisites and information required from the University of the District of Columbia (UDC) Marketing and/or IT teams before DAPS Analytics can prepare the embed integration of the Water Quality Intelligent Service (WQIS) dashboard into the existing UDC WRRI homepage.

The WQIS dashboard is currently live at udc.wqis-app.com, hosted on Microsoft Azure Container Apps. The goal is to embed this application directly into the UDC WRRI website so that visitors can interact with real-time water quality data without leaving the university's domain.

2. Recommended Integration Approach

We recommend an iframe-based embed as the initial integration method. This approach:

  • Requires minimal changes on the UDC website (a single HTML snippet)
  • Keeps the dashboard fully managed and updated by DAPS Analytics
  • Maintains security isolation between the UDC site and the dashboard
  • Can be deployed in under one business day once prerequisites are met

The embed code will look similar to:

<iframe
  src="https://udc.wqis-app.com/embed"
  width="100%"
  height="900"
  style="border: none; border-radius: 8px;"
  title="UDC Water Quality Dashboard"
  loading="lazy"
  allow="fullscreen"
></iframe>
Note: DAPS Analytics will create a dedicated /embed route that removes the application's own navigation header and sidebar, providing a clean, chrome-free view optimized for embedding. The full standalone dashboard will remain available at the current URL.

If UDC later wishes to serve the dashboard under a university-owned subdomain (e.g., wqis.udc.edu), this can be achieved with a DNS CNAME record — no re-deployment required.

3. Information Required from UDC

Please provide the following information so we can configure the embed correctly and securely.

3.1 Target Website Details

Item Details Needed
Target page URL The exact URL of the WRRI homepage or page where the dashboard will be embedded (e.g., https://www.udc.edu/causes/wrri/dashboard)
Domain(s) to whitelist All domains that will host the embed. We must whitelist these in our security headers (frame-ancestors). Examples: www.udc.edu, causes.udc.edu, wrri.udc.edu
CMS / Website platform What platform powers the WRRI website? (e.g., WordPress, Drupal, Sitecore, custom HTML, SharePoint). This determines how the iframe code is inserted.
Content Security Policy Does the UDC website enforce a Content Security Policy (CSP) header? If so, frame-src must allow udc.wqis-app.com. UDC IT may need to update this.

3.2 Layout & Design Preferences

Item Details Needed
Available width What is the content area width on the target page? (e.g., 1200px, full-width, sidebar layout). This determines responsive behavior.
Desired height Preferred dashboard height in pixels, or should it auto-expand? Typical: 800–1000px. Full-page embed is also possible.
Theme preference Should the embedded dashboard use dark mode, light mode, or match the UDC site's theme? The current UDC site appears to use a light theme.
Default view Which section should load first? Options: Main dashboard (map + metrics), Station table, Research portal, or a specific station detail page.
Navigation scope Should users be able to navigate within the embed (e.g., click a station to see detail), or should it be locked to a single view?

3.3 Technical & IT Requirements

Item Details Needed
IT contact person Name, email, and role of the UDC IT or web team member who can insert HTML into the WRRI page and modify server headers if needed.
Staging/test environment Is there a staging or development version of the WRRI site where we can test the embed before going live?
SSL certificate Confirm the target page is served over HTTPS. Browsers block mixed content (HTTPS page embedding HTTP iframe).
iframe restrictions Does the UDC hosting environment impose any restrictions on iframes? Some enterprise CMS platforms or WAFs block iframe embeds.
Custom subdomain (optional) If UDC wants the dashboard accessible at a university-owned URL (e.g., wqis.udc.edu), we need UDC IT to create a DNS CNAME record pointing to our Azure endpoint.

3.4 Branding & Attribution

Item Details Needed
UDC logo file If UDC wants their logo displayed within the embedded dashboard header, provide an SVG or high-resolution PNG with transparent background.
Attribution requirements Should the embed include "Powered by DAPS Analytics" or similar attribution? Or should it appear fully UDC-branded?
Color overrides Should the embed use UDC brand colors (Gold #FDB927, Red #CE1141, Navy #002B5C) — which are already the defaults — or match the WRRI page's color scheme?

4. What DAPS Analytics Will Provide

Once the above information is received, DAPS Analytics will:

  1. Create the /embed route — a chrome-free version of the dashboard with no sidebar or top navigation, optimized for iframe display
  2. Configure security headers — update Content-Security-Policy frame-ancestors and remove X-Frame-Options restrictions for the approved UDC domain(s)
  3. Apply theme/branding — set the default theme, colors, and attribution based on UDC preferences
  4. Provide the embed snippet — ready-to-paste HTML code with the correct dimensions and parameters
  5. Test on staging — verify the embed works on the UDC staging site before production deployment
  6. Deploy and monitor — push the embed-ready build to Azure and confirm everything renders correctly on the live WRRI page

Estimated turnaround: 2–3 business days after receiving all prerequisites.

5. Security Considerations

  • The iframe embed is read-only for public visitors — no authentication is exposed. The admin panel and data ingestion APIs are not accessible through the embed route.
  • The embed route will be restricted via frame-ancestors to only the approved UDC domain(s). No other website will be able to embed the dashboard.
  • All communication is over HTTPS with TLS 1.2+.
  • The dashboard does not set cookies or collect personal data from visitors.
  • The AI Research Assistant (chat feature) can be included or excluded from the embed based on UDC preference.
